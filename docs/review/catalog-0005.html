Judgement calls that want your eye

New in this pass. The data model called the check digit optional and left the algorithm open, so these are choices rather than transcription.

needs your call

Mod-11, not Luhn

The data model offered either. Luhn does not detect a 09↔90 transposition, which is exactly the error a warehouse keypad produces. Mod-11 with weights 8..2 catches every single-digit substitution and every transposition, adjacent or not.

needs your call

The digit covers the body, not the prefix

sku_check_digit() reads the seven digits alone. The data model says the numeric part must stand on its own because the prefix will get stripped somewhere eventually — so a digit that depended on GLA would stop validating at exactly that moment.

needs your call

Unrepresentable digits skip, they do not become X

One body in eleven wants a check value of 10. ISBN-style X would keep every sequence value but put a letter in the numeric tail. Skipping keeps the SKU numeric after the prefix — keypads, spreadsheets, scanners — and costs only sequence values, in a scheme where gaps are already normal because retired SKUs are never reused.

needs your call

Allocation lives in the database

catalog.next_mosferics_sku(dept) does the nextval loop, the skip and the formatting, so the rule exists once rather than once here and once in Python. It raises on a department prefix that no level-1 taxonomy node carries.

needs your call

The 7-digit ceiling is a RAISE, not a sequence MAXVALUE

mosferics_sku_seq is still declared AS bigint while the body holds seven digits. The allocator raises past 9,999,999 with a message that names the problem; capping the sequence instead would give a blunter error. Ten million against a sixty-thousand catalogue makes this theoretical either way.

Judgement calls for the record

Already inside 0005 before this pass, and not dictated by mosferics_data_model_v3.md. Listed because this is the first time the schema has been rendered for review.

for the record

documents is created before compliance

compliance.evidence_document_id is a real foreign key to it, so the build doc's listed order cannot be executed as written.

for the record

variants.ean is indexed but not unique

Two variants may legitimately hold the same EAN in the window between import and a confirmed multi-source merge. A unique constraint would reject the second supplier's row before review could happen.

for the record

uq_taxonomy_sibling_slug is NULLS NOT DISTINCT

Level-1 nodes all share parent_id IS NULL. Under default NULL semantics the sibling-slug rule would silently not bind them — the one level where a collision matters most, since these are the nodes that carry SKU prefixes.

for the record

sku_prefix uniqueness is a partial index

WHERE sku_prefix IS NOT NULL, so the many nodes below level 1 do not compete for a single NULL slot.

for the record

documents.attach_id is polymorphic

Its target table depends on attach_level, so no single SQL foreign key can express it. A CHECK constrains the level; the pipeline enforces the reference.

for the record

age_restricted is the only evidence exemption

Hard rule 2 is structural here — ck_compliance_evidence_required means no evidence, no row. The data model defines the 18+ knife rule as policy rather than a manufacturer statement, so it has no data sheet to point at and is named explicitly in the constraint.

for the record

Two review vocabularies, deliberately different

product_metadata.status is constrained to pending_review / verified / rejected and defaults to pending_review, per hard rule 3. products.description_status stays free text, following migration 0003 — that vocabulary is not settled yet.

-- Name: next_mosferics_sku(text); Type: FUNCTION; Schema: catalog; Owner: mos_owner
--

CREATE FUNCTION catalog.next_mosferics_sku(p_dept text) RETURNS text
    LANGUAGE plpgsql
    AS $$
        DECLARE
            v_seq   bigint;
            v_body  text;
            v_check integer;
        BEGIN
            IF NOT EXISTS (
                SELECT 1 FROM catalog.taxonomy
                WHERE sku_prefix = p_dept AND parent_id IS NULL
            ) THEN
                RAISE EXCEPTION
                    'unknown department prefix %: no level-1 taxonomy node carries it',
                    p_dept;
            END IF;

            LOOP
                v_seq := nextval('catalog.mosferics_sku_seq');
                IF v_seq > 9999999 THEN
                    RAISE EXCEPTION
                        'mosferics_sku_seq has outgrown the 7-digit body at %', v_seq;
                END IF;
                v_body  := lpad(v_seq::text, 7, '0');
                v_check := catalog.sku_check_digit(v_body);
                EXIT WHEN v_check < 10;
            END LOOP;

            RETURN 'MOS-' || p_dept || '-' || v_body || '-' || v_check::text;
        END;
        $$;


ALTER FUNCTION catalog.next_mosferics_sku(p_dept text) OWNER TO mos_owner;

--
-- Name: sku_check_digit(text); Type: FUNCTION; Schema: catalog; Owner: mos_owner
--

CREATE FUNCTION catalog.sku_check_digit(seq_part text) RETURNS integer
    LANGUAGE sql IMMUTABLE STRICT
    AS $_$
            SELECT (11 - (SUM(substr(seq_part, 8 - i, 1)::integer * (i + 1))::integer % 11)) % 11
            FROM generate_series(1, 7) AS i
            WHERE seq_part ~ '^[0-9]{7}$'
        $_$;
